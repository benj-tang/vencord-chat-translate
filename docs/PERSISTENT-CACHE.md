# 本地译文缓存

消息译文默认保存在本机，退出 Discord 或重启电脑后仍可读取。
输入框的草稿译文不写入这个缓存。

## 默认设置

- `Persistent Cache Enabled`：开启；关闭后只使用内存缓存，不删除已有文件。
- `Cache Retention Days`：30 天，可配置 1–365 天。
- `Cache Max Entries`：5000 条，可配置 100–20000 条。
- 文件大小上限：10 MiB，按实际 UTF-8 字节数计算。
- 内存热缓存：1000 条。
- 插件设置的“清空翻译缓存”：同时清空本地文件内容和内存缓存。

路径为 `~/.cache/chat-translate/translations-v1.json`。
POSIX 系统目录权限为 0700、文件为 0600；Windows 依赖当前用户目录的 ACL。
这是私密明文文件，没有加密；译文可能包含姓名、金额及原文保留的中文。

文件中不保存独立的原文、作者、频道标识、端点或密钥字段。
缓存键是 SHA-256 指纹；原文代码、URL 和 Discord 提及在译文中替换成短占位符，
读取时根据当前消息校验和恢复。文件还保存创建及访问时间，用于过期和淘汰。

## 复用与失效

同一消息内容和版本、目标语言、保留词／术语表及实际服务端点／模型／思考档位
相同时，优先读取本地译文，不请求翻译服务。
成功的邻近消息仍可作为其他待译消息的可见上下文。

重启本身不再使有效的消息译文失效。以下情况仍可能重新请求：

- 内容或版本、目标、术语表或服务身份变化。
- 保存超过期限，或因条数／字节上限被淘汰。
- 关闭持久缓存、主动清空缓存、明确重新翻译。
- 文件权限不安全、磁盘不可用、文件损坏或占位符校验失败。

界面服务配置变化会清空内存译文；私密 profile 中的模型改动后请清空缓存。
密钥轮换不改变持久缓存服务身份。每次写入使用该请求实际服务的身份，
不把中途切换 profile 前的结果保存到新模型名下。

过期时间按创建时间计算，命中不会延长。读取／写入时清理过期记录；
应用关闭期间没有后台清理任务。文件仍在时也不表示过期项会被复用。
每日字符预算目前仍是内存计数，客户端重启会重置；它与持久译文缓存分开。

## 可靠性与诊断

并发写入串行合并，再写入私密临时文件、同步文件数据并原子替换。
异常文件按缓存未命中处理，正常翻译继续；写入失败不会撤掉已经成功的译文。
只读 lookup 的权限／符号链接检查不会触碰链接目标。

异步读完缓存后，调度器重新检查消息内容、版本和可见性。
自动翻译仍只针对当前阅读视窗，缓存不触发历史消息检索。
“查看翻译状态”显示条数、文件大小、此次启动的命中次数和不可用／重建状态，
不展示缓存原文或指纹。

测试覆盖文件跨实例读取、全新引擎复用、服务身份隔离、过期、LRU、UTF-8 字节上限、
并发写入、损坏文件、私密权限、符号链接、提及恢复、强制重译和可见性重检查。
