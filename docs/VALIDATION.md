## Magpie 真实接入

使用用户现有家庭网关，实时模型目录包含 `deepseek/deepseek-v4-flash`。
本机 profile 使用此完整 ID 和 `low`；不改动网关、Paseo 或路由器配置。
profile 在仓库外，已读回权限 0600。构建产物不嵌入密钥。

独立 Electron 42.11.1 与本机 Discord 的框架版本一致。下载的官方归档已对照
对应 npm electron 包内 checksum 验证。使用插件实际打包的原生模块，
通过 `net.fetch` 完成系统信任 HTTPS、Bearer 鉴权及真实 Chat Completions 请求。
没有关闭证书验证，也没有读取 Discord 聊天。

最终合成文本复测：

| 场景             | 输入                  | 返回              | 耗时    |
| ---------------- | --------------------- | ----------------- | ------- |
| 接收消息与上下文 | 3 条待译＋1 条上下文  | 3 条译文          | 4884 ms |
| 中文草稿译成英文 | 1 条待译              | 1 条英文          | 1111 ms |
| 50 条上下文批次  | 45 条待译＋5 条上下文 | 45 条完整 ID 译文 | 6928 ms |

金额、占位符、否定条件和上下文出金指代通过对应样例检查。
第一轮将出金审批误指为账户审批，补强上下文条件/代词提示后，同句复测为
“在出金获批之前，不要关闭账户”。这只证明该样例改善，不代表金融译文准确率已验收。
接口返回的独立思考字段不进入展示；`thinking: disabled` 的探测仍产生思考 token，
因此本机配置只承诺 low 档位，不承诺关闭思考。
耗时来自单次短文本采样，不是长期性能或接近字符上限的吞吐保证。

本机忽略的 `.cache/magpie-smoke.json` 保存完整合成结果。
这些出金句子完全是测试文本，不能据此判断 P1 或其他服务的真实出金状态。
