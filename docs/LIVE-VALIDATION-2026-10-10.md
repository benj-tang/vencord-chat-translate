| 版本                     | 已观察消息 | 视窗相交 | 识别         | 待译＋上下文 | 返回 | 原生调用耗时 | 思考 token | 接口生成总 token |
| ------------------------ | ---------- | -------- | ------------ | ------------ | ---- | ------------ | ---------- | ---------------- |
| 首次直接草稿／范围修复   | 41         | 11       | 1 次 / 11 条 | 11＋0        | 11   | 8655 ms      | 尚未记录   | 尚未记录         |

| 公告频道第二范围保存     | 14         | 2        | 1 次 / 4 条  | 4＋0         | 4    | 21844 ms     | 4564       | 5137             |

通过启用范围后实际自动产生的请求读取诊断，没有为这些成功自动批次点击单条翻译。
因此它们证明频道视窗自动批量调用，而不只是 provider 合成探测。
公告批次诊断是请求完成后的读取：开始请求和之后译文改变布局，
相交数不必与请求目标数一致；需要时序观测才能判断每次提交的具体视窗。
耗时从原生调用开始计，另有连续可见 1 秒的入队时间。
这些计数不证明所有窗口尺寸、滚动、焦点或历史加载组合都已实机覆盖。
诊断只记录计数，不把实际聊天原文、用户名称或 ID 保存到仓库。

## 实际失败汇总与恢复

只在本机将私密 profile 临时移至同目录，30 秒定时恢复，未改任何 HomeLab 服务。
恢复后 SHA256 和权限与之前一致。公告频道向上滚动进入未缓存消息后：

- 原生调用 1 条目标＋1 条上下文，3 ms 后失败，无 token 计数。
- 实际界面只有频道状态“连接需检查”、1 条未译及“重试当前视窗”，原文保持可见。
- 恢复后点击汇总重试，1 条目标＋1 条上下文返回 1 条译文，7577 ms，
  思考 1541、总生成 1756 token。错误提示消失，状态恢复“自动开启”。
- 成功邻近项只作为上下文，本次没有再次作为待译目标。

这验证凭证不可用的暂停／汇总／恢复路径，不验证真实 429、网络超时和 5xx 退避。

## 关闭思考探测

独立 Electron 42.11.1 使用同一本机 profile、系统证书信任和插件实际提示词。
每条合成待译文本包含金额、占位符、出金审核和否定条件；每次带 5 条合成上下文。
所有下列探测均返回完整结果，金额与占位符通过检查。
只记录 token 计数和思考字段长度，不保存思考正文。

| 接口      | 参数                   | 待译＋上下文 | 耗时     | 思考 token | 接口生成总 token |
| --------- | ---------------------- | ------------ | -------- | ---------- | ---------------- |
| Chat      | reasoning_effort: low  | 11＋5        | 4594 ms  | 622        | 1098             |
| Chat      | reasoning_effort: none | 11＋5        | 3997 ms  | 587        | 1019             |
| Chat      | reasoning_effort: low  | 45＋5        | 12103 ms | 1545       | 3483             |
| Chat      | reasoning_effort: none | 45＋5        | 10267 ms | 1189       | 3127             |
| Responses | reasoning.effort: none | 11＋5        | 7021 ms  | 1047       | 1523             |
| Responses | reasoning.effort: low  | 11＋5        | 5870 ms  | 901        | 1377             |
| Responses | reasoning.effort: none | 45＋5        | 9812 ms  | 1178       | 2936             |
| Responses | reasoning.effort: low  | 45＋5        | 10954 ms | 1365       | 3393             |

结论：当前完整 Magpie 链路中，上述 none 参数没有关闭思考。
少数 none 样本较快不能解释为关闭成功，也不能用单次顺序探测估计稳定提速。
保留 low，不新增一个虚假的“关闭思考已生效”开关。

另外下载检查了 Magpie v0.1.1130 源码中的 effort 归一化、模型档位适配和跨协议转换。
源码表明 none 在某些路径会按 low 解析，转换后的关闭需模型能力包含 none，
原协议请求也会按模型档位拟合。该逻辑支持“网关能力登记／映射可能影响关闭”的解释；
当前运行服务 `/v1/models` 已读回：路由声明支持思考，档位 low/high/max，
端点列为 Responses，没有声明 none。运行服务精确版本及内部偏好配置仍未验证，
不能据此断定唯一根因。官方关闭参数及额外独立探测见 [思考调研](DEEPSEEK-THINKING.md)。
没有改动网关或绕开用户指定端点。

## 剩余验收

- 输入框等待转圈已实现，但本次截图均在请求完成后取得，尚无进行中视觉验收。
- 三空格关闭后的普通输入、全部八种样式、按样式切换不产生新请求尚未逐项实机验收。
- 凭证不可用的汇总失败已实机验收；瞬时超时／429／5xx 退避、手动消息翻译／关闭／重译完整流程尚未完成实机验收。
- 角色／频道提及和未知名称通过合成回归，真实界面目前只验收用户提及。
- 快速滚动、长消息顶部、最小化、线程切换、50 条真实可见消息及高字符批次需进一步验收。
- 实际聊天金融译文准确率、长期内存和真实账单未验收。

对应规则、批次、失败、过期草稿及名称解析已有本地回归，不把这些测试替代实机验收。
安装后用户继续浏览其他服务器；最终核对保留了用户所在频道及原有继承设置。
继续验收前应读取当前界面并保留现有草稿。

键为 64 位十六进制指纹，无原始 Discord 提及 token；未输出或提交译文正文。

这验证客户端新进程读取磁盘及不重复请求，没有重启整台电脑；

实际 UI 清空／关闭开关及长期淘汰尚未逐项实机覆盖，回归测试覆盖清空、
